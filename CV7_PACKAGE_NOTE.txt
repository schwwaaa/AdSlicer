AdSlicer CV-7 — Production Integration

Baseline:
- User-provided AdSlicer-nextgen.zip
- Git baseline commit: 5d8ae57 feat(opencv): add full structural segmentation with raised-VHS-black recovery
- CV-6.1a handoff treated as the integration contract.

What changed:
- Added Detection / Segmentation Engine selection:
    OpenCV Adaptive (default)
    Legacy
- Added OpenCV policy selection:
    Complete Segments (default)
    Every Separator
- Promoted the validated CV-1 -> CV-2 -> CV-3 -> CV-6/CV-6.1a path into the normal AdSlicer job.
- Preserved the original Legacy production processor as a fallback.
- OpenCV production output now exports full-coverage structural clips to:
    <output>/<recording>/segments/
- OpenCV does NOT invent show/commercial labels. CV-6.1a validates structural boundaries, not semantic content classification.
- Chapters mode remains available and writes Segment N chapter markers across the complete source.
- Dry Run remains available and writes diagnostics without media export.
- Full coverage is a hard render gate: uncovered or overlapping source time aborts the OpenCV production export.
- OpenCV diagnostics are automatic under:
    <output>/<recording>/logs/opencv/
- Legacy-only tuning controls are disabled in the UI while OpenCV Adaptive is selected.
- Existing Default / Noisy VHS / Broadcast Strict presets explicitly switch to Legacy because their thresholds belong to the old detector.
- Cargo default features now include opencv-analysis so the normal app contains the OpenCV production engine.
- ./build.sh dev configures Homebrew OpenCV/libclang discovery before launching Tauri dev.

Regression harness:
- ./test-opencv.sh --synthetic now also runs the CV-7 production integration probe.
- On synthetic structural corpus 09, the CV-7 check expects:
    Complete Segments = 4 segments, zero-loss coverage
    Every Separator  = 5 segments, zero-loss coverage
